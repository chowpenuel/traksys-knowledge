# Connect Example: XML Import with Web Service Endpoint

*Source: https://portal.parsec-corp.com/hc/en-us/articles/19659786617747-Connect-Example-XML-Import-with-Web-Service-Endpoint*
*Last updated: 2025-05-21T22:12:41Z*

---

Applies To | TrakSYS 12.0.1+

### Summary

This article includes an example of performing an XML Import using a Web Service Endpoint Interface Definition combined with an XML Payload Definition. When the Web Service is called, it executes a Module to process the imported data. The Module will contain a Module Script Step that adds the record to the tJob table.

Note that this example is meant to be used as a simple starting point for using TrakSYS Connect. Therefore, not every feature within the Web Service Endpoint Interface Definition and XML Payload Definition is used. For more technical information about TrakSYS Connect and the settings contained within each of the entities, the [TrakSYS 12 Reference Documentation](https://support.parsec-corp.com/refdocs/12/traksys/getting-started.html) can be referenced.

### Creating a Payload Definition

The first step to using TrakSYS Connect is creating and configuring an XML Payload Definition. This helps define what type of data is used and what the expected XML data structure should be when importing and exporting content. The steps to create an XML Payload Definition can be found **[here](https://portal.parsec-corp.com/hc/en-us/articles/24736728437139)**.

### Creating an Interface Definition

The following steps show how to create and configure an Interface Definition. This entity defines _how_ the the data will be communicated. In this case, data will be imported at a Web Service Endpoint from a Web Service Call.

  1. In the TrakSYS Web, navigate to **Developer | Connect | Interface Definitions**.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/23901250316947)  
  

  2. In the first slice, create a new Interface Definition Group if one does not already exist. Otherwise, select an existing Interface Definition Group.
  3. In the second slice, click the New link to create a new Interface Definition.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/23901237514003)  
  

  4. Select the Web Service Endpoint option on the resulting page.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/23901250326419)  
  

  5. Provide a Name and Key for the Interface Definition.   
  
![](https://portal.parsec-corp.com/hc/article_attachments/27575985960339)  
  

  6. Next, click the blue picker icon under the Message Payload Definition property and select the XML Payload created in the previous section.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/23901237530771)  
  

  7. Provide a value for the Module Trigger Key setting. This will be the Module Key that will be called to process the XML data when it is imported. Then, provide value for the Route field. This will help define the Web Service Endpoint, which will be called by other clients. In this example, since data is being imported and processed, ensure that the HTTP Method setting is set to POST.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/23901250380947)  
  

  8. The final result should look similar to the following:  
  
![](https://portal.parsec-corp.com/hc/article_attachments/27575971576211)  
![](https://portal.parsec-corp.com/hc/article_attachments/27575971587731)  
  

  9. Click the Save button to create the Interface Definition.



#### Checking the Endpoint URL

At this point, the Web Service Endpoint has been created and can now be called by client applications. The URL created for this Endpoint will depend on the value specified in the Route setting defined in the section above on step 7. These steps show how to check the full Endpoint URL for this Interface Definition:

  1. Select the newly created Interface Definition and click the Copy Endpoint URL link under the Actions section of the third slice.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/23901803142035)  
  

  2. The following page will display the full URL that has been generated for the Endpoint. Click the copy button to copy the link to the clipboard.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/23986528774035)  
  
It is highly recommended to paste this URL into a different location for reference and documentation purposes. For the purpose of this example, this URL will be needed in later steps to make a web call to the Endpoint.



#### Performing a Full Compile

Now that both the Interface and Payload has been configured, a full compile is needed. This process will create and compile all Classes automatically generated by Connect based on the configuration.

**Note** : it is **strongly** recommended to turn off the Logic Service before performing a Full Compile. Otherwise, there is a chance that this process can fail. Additionally, a Full Compile **must** be performed every time changes are made to Interface Definitions or Payload Definitions. This helps ensure that all classes generated by Connect are properly created.

  1. In the TrakSYS Web, navigate to **Developer | Scripts | Web**.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/23903566903571)  
  

  2. In the first slice, click the Compile button.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/23903566907795)  
  

  3. In the confirmation, click the Full Compile button to start the compile process.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/23903551994387)  
  

  4. If the process is a success, the following confirmation dialog should be displayed:  
  
![](https://portal.parsec-corp.com/hc/article_attachments/23903566915475)



### Creating a Module

Now that the Payload Definition and Interface Definition have been created, a Module will be created to import the data from the XML file. The steps to create this Module can be found **[here](https://portal.parsec-corp.com/hc/en-us/articles/24996723474451)**. Note that it is possible to use TrakSYS Connect in other areas of the application (e.g., such as on a page within the TrakSYS Web, within a Workflow Diagram, within Script Classes, and more). However, the code in each of these areas may be slightly different than what's shown in the article.

### Making Web Calls to the Endpoint

At this point, it should be possible to make web calls to this endpoint to process data. [This article](https://portal.parsec-corp.com/hc/en-us/articles/23998623698451) contains an example of configuring TrakSYS Connect to make web calls. The example assumes that the steps in this article have been followed and the endpoint already exists. The example makes calls from within TrakSYS to an endpoint that also exists within TrakSYS. In real world scenarios, it is more likely that the calls will be made to external endpoints instead. If a separate application is used to make the calls, it should contain the ability to send the XML data in the exact format that was defined in the Payload Definition.

  1. Using the web call example from the article linked above, the following XML was generated to make the call:  
  

         
         <Job>
           <ID>17</ID>
           <Name>Imported Job 16</Name>
           <AltName>Job16</AltName>
           <ProductID>12</ProductID>
           <Notes>This is an imported job</Notes>
         </Job>
         

  2. To verify the results, query the tJob table. The new record included in the XML content should now be included in the table.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/27576011095955)
