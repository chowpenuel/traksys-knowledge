# Notification Definition

## Summary

### Entity Name

Notification Definition

### Database Table Name

`tNotificationDefinition`

### API Object Name

`DbNotificationDefinition`

### Entity Description

A Notification Definition is a content template and specification for a message that can be sent when a specified condition occurs. It represents the content and format of an email or textual based message. Because Notification Definitions are defined independently of the logic that triggers the message, they can be re-used in many different places in the configuration, reducing the need to constantly re-define and configure similar message structures. When a specific notification is configured (such as based on a Tag change), a Notification Definition is selected. When the configured condition is triggered, the Notification Definition is retrieved and processed before sending.

### Entity Description | Content Expressions

The Title, Body and attributes of its Notification Attachment sub-items can all be constructed using the same TrakSYS expression syntax that is used in the configuration of TS Web dashboard charts and HTML web parts. This allows dynamic content to be produced such as displaying live Tag values, values passed in from the Logic Service execution and even results from data source queries embedded in the message definition.

### Entity Description | Passing Arguments

In order to contextualize the generic message defined in the Notification Definition, the content can utilize source specific arguments that are sent in from the calling notification trigger. Arguments are accessed using the `{args|ArgumentName}` expression syntax. Each notification type (Tag, System, Event Definition, Function Definition, Task Definition, Logic Service, etc…) passes a set of built in arguments. In addition, user defined arguments can be configured and passed to the message. For instance when a notification is triggered from the start of a specific Event Definition, the Event Definition's ID and Name can be accessed using the `{args|EventDefinitionID}` and `{args|EventDefinitionName}` expressions. This allows a generic message to be created that can be utilized by several Event Definitions in the configuration.

## Properties

`Notification Definition Group [ NotificationDefinitionGroupID ]`

Specifies the parent Notification Definition Group.

`Title Content [ TitleContent]`

Specifies the text that will be included as the subject of the message. This content can contain TrakSYS expressions.

`Body Content [ BodyContent ]`

Specifies the text that will be included as the main body of the message. This content can be simple text or HTML, and can contain TrakSYS expressions. When using HTML in the message, note that the ability for mail and message reader client software to display HTML content varies significantly. Messages should be tested on all prospective clients.

`Message Type [ MessageType ] : ETS.Core.Enums.NotificationDefinitionMessageType`

Specifies the Message Type of the Notification Definition.

* **EmailLegacy** = 0
* **EmailRetrieveAndEmbedLegacy** = 1
* **AlertLegacy** = 10
* **WebHook** = 20

**Email** - When this attribute is selected, a standard email message containing the `Body Content` and any configured attachments will be sent.

**Email (Retrieve And Embed)** - When this attribute is selected, the Body Content of the message is interpreted as a (and expected to be) full web URL address. When the message is rendered, the specified URL is accessed and the returned web page content is included as the message's body content. When using this feature, note that the ability for mail and message reader client software to display HTML content varies significantly. Messages should be tested on all prospective clients.

{% hint style="warning" %}
The Email (Retrieve And Embed) feature was intended for use with Legacy WEBTrak and has been deprecated. Attempting to use this feature with pages in the TrakSYS Web may cause rendering issues and some elements may not appear at all. This feature will be removed in a future TrakSYS update or version.
{% endhint %}

**Alert** - When this attribute is selected, Alerts will be sent to users within the TrakSYS Web.

**Web Hook** - When this attribute is selected, a message will be sent to a specific URL. The URL must be specified within the `Title Content` of the Notification Definition.

`Status Type [ StatusType ] : ETS.Core.Enums.NotificationDefinitionStatusType`

Specifies the Status Type of the Notification Definition. This option is only enabled when the `Message Type` is set to `Alert`.

* **None** = 0
* **Success** = 1
* **Information** = 2
* **Warning** = 3
* **Error** = 4

`Keep Forever [ ShouldRetain ]`

When checked, records in `tNotification` generated by the Notification Definition will be moved to `tNotificationHistory`. Any attachments they contain will also be moved to `tNotificationHistoryAttachment`.
