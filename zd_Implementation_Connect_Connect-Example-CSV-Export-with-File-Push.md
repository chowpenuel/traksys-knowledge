# Connect Example: CSV Export with File Push

*Source: https://portal.parsec-corp.com/hc/en-us/articles/23777895304595-Connect-Example-CSV-Export-with-File-Push*
*Last updated: 2025-05-21T22:13:40Z*

---

Applies To | TrakSYS 12.0.1+

### Summary

This article includes an example of performing an CSV Export using a File Push Interface Definition combined with an CSV Payload Definition. The file export is triggered by calling a Module's Trigger Key. When the Module executes, a Module Script Step will create the values and data structure. It will then pass this information to the Interface Definition to create the CSV file with the appropriate data.

Note that this example is meant to be used as a simple starting point for using TrakSYS Connect. Therefore, not every feature within the File Push Interface Definition and CSV Payload Definition is used. For more technical information about TrakSYS Connect and the settings contained within each of the entities, the [TrakSYS 12 Reference Documentation](https://support.parsec-corp.com/refdocs/12/traksys/getting-started.html) can be referenced.

### Creating a Payload Definition

The first step to using TrakSYS Connect is creating and configuring a CSV Payload Definition. This helps define what type of data is used and what the expected CSV data structure should be when importing and exporting content. The steps to create an CSV Payload Definition can be found **[here](https://portal.parsec-corp.com/hc/en-us/articles/24736404202899)**.

### Creating an Interface Definition

The following steps show how to create and configure an Interface Definition. This entity defines  _how_ the the data will be communicated. In this case, data will be exported using a Module Script Step which passes the information to a File Push Interface Definition.

  1. In the TrakSYS Web, navigate to **Developer | Connect | Interface Definitions**.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/24293754494867)  
  

  2. In the first slice, create a new Interface Definition Group if one does not already exist. Otherwise, select an existing Interface Definition Group.
  3. In the second slice, click the New link to create a new Interface Definition.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/24293754516115)  
  

  4. Select the File Push option on the resulting page.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/24293724632467)  
  

  5. Provide a Name and Key for the Interface Definition.   
  
![](https://portal.parsec-corp.com/hc/article_attachments/24293724649747)  
  

  6. Next, click the blue picker icon under the Message Payload Definition property and select the CSV Payload created in the previous section.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/24297874481427)  
  

  7. Under the File Service section, provide values for the following settings:  
  
**Target Path** \- This is the folder that will contain the CSV file once it has been generated.  
  
**Login** and **Password** \- This is the credentials for the account used to create the files. The specified account should have the proper access to the folder location along with full Read and Write access to all contents within it.  
  
**Target File Name** \- This is the name that will be provided to the CSV file when it is generated.  
  
For the purpose of this example, the file will be created in the default Users\Public folder as this folder has fewer overall permission restrictions. However, using this folder location is **not** required.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/25325725193107)  
  

  8. The final result should look similar to the following:  
  
![](https://portal.parsec-corp.com/hc/article_attachments/25325997229459)  
  

  9. Once all changes have been made, click the Save button to create the Interface Definition.



#### Performing a Full Compile

Now that both the Interface and Payload has been configured, a full compile is needed. This process will create and compile all Classes automatically generated by Connect based on the configuration.

**Note** : it is **strongly** recommended to turn off the Logic Service before performing a Full Compile. Otherwise, there is a chance that this process can fail. Additionally, a Full Compile **must** be performed every time changes are made to Interface Definitions or Payload Definitions. This helps ensure that all classes generated by Connect are properly created.

  1. In the TrakSYS Web, navigate to **Developer | Scripts | Web**.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/24298050489491)  
  

  2. In the first slice, click the Compile button.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/24298036681363)  
  

  3. In the confirmation, click the Full Compile button to start the compile process.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/24298036694803)  
  

  4. If the process is a success, the following confirmation dialog should be displayed:  
  
![](https://portal.parsec-corp.com/hc/article_attachments/24298036707731)  




### Creating a Module

Now that the Payload Definition and Interface Definition have been created, a Module will be created to export data to a CSV file. The steps to create this Module can be found **[here](https://portal.parsec-corp.com/hc/en-us/articles/24997184387475)**. While the steps in the article use an XML Payload, similar code can be used for CSV Payload types as well. Note that it is possible to use TrakSYS Connect in other areas of the application (e.g., such as on a page within the TrakSYS Web, within a Workflow Diagram, within Script Classes, and more). However, the code in each of these areas may be slightly different than what's shown in the article.

### Module Execution and File Creation

Now that the configuration has been created, the Module can be triggered so that the CSV file can be generated. While this can be achieved in multiple different ways, the easiest way to do this for testing purposes is through the Data Management page within the TrakSYS Web. The following steps describe how to do this.

  1. Navigate to **Administration | Services | <YourDataManagementServiceName>**.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/24299743688211)  
  

  2. On the resulting page, find the desired Module and click the Execute button.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/24299708181395)  
  

  3. Once the Module is done executing, the file should be generated in the folder specified in the Target Path field of the Interface Definition. In this case this setting was defined as **C:\Users\Public\Documents\Source**.  
  
![](https://portal.parsec-corp.com/hc/article_attachments/25326405283859)  
  

  4. The contents of the file should show the exported values:  
  
![](https://portal.parsec-corp.com/hc/article_attachments/25326372379923)  
  

  5. Finally, a record should be created in the `tInterfaceTransaction` table for this transaction.
