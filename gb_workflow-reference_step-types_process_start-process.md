# Start Process

This Step Type allows for a new Process to be spawned and started. The Process started will begin and execute separately (asynchronously) from the originating Process. When this Step is executed, a **Start Process Request** is created. It sometimes takes a few seconds for a new Process Request to be picked up and started. In addition, the Process start may error (incorrect starting parameters, etc...). This Step will use the **Check Every** and **Timeout After** properties to wait until the requested Process reports that it has successfully started before completing execution.

Specifies an optional unique identifier (within the Process Definition) for the Step.

#### Process Definition Key

Specifies the Process Definition `Key` to be started.

### Process Parameters

Allows for passing values into a new Process. The Parameters passed must match up to the Process Parameter Definitions defined on the target Process Definition.

* **Name** - Specifies the target Process Parameter Definition `Key`.
* **Data Type** - Specifies the Data Type of the value being passed.
* **Default Value** - Specifies the default value to be passed if the actual value cannot be located using the `Key` specified below.
* **Key** - Specifies a `Key` from the **Process Values** to retrieve the value to be passed.

#### Process Key

Optionally specifies a unique value to be assigned as the identifier for the new Process.

#### Process Step Definition Key

Optionally specifies a Process Step `Key` where the new Process should start. This is for cases when the target Process Definition has more than one possible Start Steps.

#### Entity ID

Optionally specifies an integer value to be recorded as the `Entity ID`, helping to identify the new Process that will be started.

#### Entity Key

Optionally specifies an string value to be recorded as the `Entity Key`, helping to identify the new Process that will be started.

#### System ID

Optionally specifies an integer value to be recorded as the `System ID`, helping to identify the new Process that will be started.

#### Description

Optionally specifies an string value to be recorded as the `Description`, helping to identify the new Process that will be started.

Specifies a span of time after which the Step will check/run its periodic execution. For instance, if **Hours** = 1, **Minutes** = 5, **Seconds** = 8, then a Step will execute every (1 \* 3600) + (5 \* 60) + 8 = 3908 Seconds.

## Hours

Specifies an (integer) number of hours.

## Minutes

Specifies an (integer) number of minutes.

## Seconds

Specifies an (integer) number of seconds.

## Force Check Key

Specifies a key that can be used to programmatically force a check.

Specifies a span of time after which a Step will **Timeout** and exit execution.

For example, if `Hours` = 1, `Minutes` = 5, `Seconds` = 8, then a Step will timeout (exit with a Timeout result) if it does not complete successfully after (1 \* 3600) + (5 \* 60) + 8 = 3908 Seconds.

This selection controls the behavior of a Step when an internal error is encountered.

**End Process** - (Default) When a Step error occurs, the entire Process is ended. This occurs even if other parallel branches are executing.

**Resume with Failure** - When a Step error occurs, the Step stops executing and completes, setting the following outgoing **Process Values**...

* **Result.Success** = False
* **Result.Error** = True
* **Result.Message** = ...some details describing the error...

Upon completion, this Step Type automatically adds the following values/**Keys** to the **Process Values**. These values can be used to write to Process Parameters via the **Outputs** tab, and can also be consumed by subsequent Steps.

### ProcessID

Contains the `ID` for the Process that was created as a result of this Step's execution.

### ProcessKey

Contains the `Key` for the Process that was created as a result of the Step's execution. This is typically a GUID generated by the Workflow Service on Process creation. If a Process Key was provided as one of the Step properties, this will return the same value specified.

### ProcessStartDateTime

Contains the date/time stamp when the Process was created and started by the Workflow Service.
