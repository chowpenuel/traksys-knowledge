# Common Entity Properties

The following properties are common to many entities within TrakSYS. To simplify the documentation listing, they have been described in this common section, and not repeated in each of the entity definition pages that follow. Note that not every entity shares every one of these properties. The related database table, or API object can be checked to get a listing of which properties/fields are available for each entity.

{% hint style="info" %}
If an entity page lists no properties, that entity only has common properties.
{% endhint %}

## Properties

`ID [ ID ]`

The unique integer identifier for the entity within the database table. This ID is automatically generated by TrakSYS as each new record is added to the table.

`Name [ Name ]`

Specifies a descriptive Name for the entity. This property is used for display in most areas of the application where the entity is rendered.

`AltName [ AltName ]`

Specifies an optional, alternate name for the entity. The AltName property is typically used when a dual language user interface is required for displaying configuration entities (such as Category Names). For example, the Name property would be used for the English term, and the AltName property for the Spanish term. There is no infrastructure for automatically displaying the AltName. Extensibility, special queries and scripting along with the language identifier for the current user must be used to display either the Name or AltName.

`Description [ Description ]`

Specifies a longer, single-line, textual description for the entity. This property is generally used for describing optional details for the entity and is displayed in some areas of the application where space permits.

`Notes [ Notes ]`

Specifies a longer, multi-lined, textual description for the entity. This property is generally used for documentation of details pertaining to the entity. It is typically not displayed in the standard interfaces of the application.

`External ID [ ExternalID ]`

Specifies a string that can be used to identify the entity, but that exists as an identifier in some external system. As an example, a TrakSYS System may be configured for each production line (called Line 1, Line 2 and Line 3), however data exchange must occur with an external maintenance software that lists the lines as assets and identifies them with codes (PL23\_L1, PL23\_L2 and PL23\_L3). The External ID property can be used to store the maintenance software code for each System, allowing some relational linkage to occur during data exchange.

`Site [ SiteID ]`

Specifies the parent TrakSYS Site for the entity. Association with a Site means that this entity is only accessible via the standard user interfaces and execution, when within that Site's context (requiring the user to have the appropriate rights). Typically only entities at the top of the relational hierarchy have SiteID fields in the database. Entities without Site properties may be indirectly linked to a specific Site via their parent relationships.

`Key [ Key ]`

Specifies a user-defined string that uniquely identifies the entity. Usually this Key value must only be unique within the entities direct siblings, however there are some entities where the Key must be universally unique ac across all instances. The Key is typically used for programmatic/scripting access to a specific entity when hard coding lookups. This method is preferred over using database IDs as those may change from implementation to implementation, or over time as a configuration evolves.

`ENTITY Type [ ENTITYTypeID ]`

Specifies a user defined Type used for organizing and reporting against this entity. User defined types can be created (for entities that support this) in the configuration user interface. Types can also be useful for dogmatically handling different subsets of entities from scripting and other extensibility.

`Color [ Color ]`

Specifies a color to be used in association with the entity. This color is used in areas of the application where the entity is displayed in conjunction with some color coding (chart bars, slices, etc...).

`Color CSS [ ColorCss ]`

Specifies a CSS color to be used in association with the entity. This color is used in areas of the application where the entity is displayed in conjunction with some color coding (tiles, etc...).

`Icon CSS [ IconCss ]`

Specifies an icon (CSS class) to be used in association with the entity. This icon is used in areas of the application where the entity is displayed (tiles, etc...).

`Script Class Name [ ScriptClassName ]`

Specifies the class name that will contain code that will run for this entity. The class name specified here must be implemented as an Script Library in the Developer section of TS Web.

`Show in Reports [ ViewInReports ]`

Specifies if the entity is displayed in standard reports and report pickers.

`Display Order [ DisplayOrder ]`

Specifies the display sort order for this entity. The Display Order is automatically generated by TrakSYS as each new record is added to the table. The value is used in conjunction with other sibling entities at the same level of display. The actual value of the Display Order is not relevant, other than if it is higher or lower than the Display Order of its related siblings.

`Enabled [ Enabled ]`

Specifies if this entity is actively considered within standard functionality. An entity is typically disabled when it is no longer required for future data collection or functionality, but is still required in order to contextualize historical data that has been captured against it (since deleting the entity from the database usually results in the clearing of any associated data).

`Is Template [ IsTemplate ]`

This field indicates if the entity is a part of a Template System. All child entities in the hierarchy below a System that is created as a Template will have this property set to 1. This field is managed internally by TrakSYS.

`Template Parent ID [ TemplateParentID ]`

For entities that are part of a Template System Child (based on a Template System), this field references the related parent entity. When configuration changes are made to the Template Parent, those changes are propagated down to any entities that reference it within this field.

`Modified Date/Time [ ModifiedDateTime ]`

This is an internal use only database field used by TrakSYS to track when the last time any other field in the table record was changed. It is managed by TrakSYS database triggers and is updated regardless of how the record was modified. Implementations are free to read from this field as needed, but should not modify it manually.

`Uploaded Date/Time [ UploadedDateTime ]`

This is an extensibility field that may be used for any entity/table row to track the last time the data in that row has been "synched" with an outside source. The typical use is for uploading data from an individual site installation, to a centralized data store. The Uploaded Date/Time can be updated by data transfer script indicating when that row was last transferred. Other logic can be built comparing the Uploaded Date/Time with the Modified Date/Time to determine is a particular row should be transferred again (because updates were made since the last sync).

`GUID [ Guid ]`

This field is automatically populated with a globally unique identifier (a .NET GUID string) when a record is created from within TrakSYS or the API. It has no built in function, however it can be useful in scenarios when publishing common configuration across different site implementations.

For example, a common Category applied to several different sites may end up with different IDs in each site's database. If the common Category is deployed by custom tooling, its GUID can be set to the same value across all sites, allowing centralized reporting to treat the Categories with different IDs as the same entity.

Note that when using the API to create or insert entities, if the GUID property is left empty, the API will generate a new, unique GUID on insert. However, if a specific GUID is set to the property before insert, the assigned value will be used.

`Is Read Only [ IsReadOnly ]`

This field indicates if a Configuration or UI entity is read only. When true, the user will have View permissions only for the entity, superseding any existing permissions (can be overridden).

`Template Data [ TemplateData ]`

Intended for Global Solution Template scenarios, data can be entered in this field to assist with App creation and deployment as well as differentiation in Downstream databases.

`Page Key 01 - 03 [ PageKey01 - 03 ]`

These extensible fields are used for conditional logic implemented using custom code. Depending on the conditions of the code, these fields can be used to redirect users to specific pages using the Page Definition Key. These fields are available on the Type tables (e.g., tAreaType, tDeviceType, tEventCodeType, etc.).

`Script Class Name 01 - 03 [ ScriptClassName01 - 03 ]`

These are extensibility fields used for conditional logic implemented using custom code. Depending on the logic of the code, these fields can be used to execute specific Script Classes by referencing the Script Class Name. These fields are available on the Type tables (e.g., tAreaType, tDeviceType, tEventCodeType, etc.).
